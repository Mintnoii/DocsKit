# Design: 引擎纯度与声明式重构

## Context

DocsKit 定位是编译型知识库的通用纯函数库，`AGENTS.md` 写明「底层引擎不写死具体业务」与「内核不写死任何具体工程名或目录名」。实测 `src/core/` 里却塞满了 Ghost 与 TeamWiki 的卡片模板、提示词和诊断句子，另有二十余处散落阈值与上百处正则。

qing 的原声纠偏锁定三个点：方法里写死固定中文、`normalize.ts` 掺杂选择器与正则、`dedup.ts` 硬编码 `0.35 / 0.65`。`MIND.md` 维度 3 的真源进一步要求数据流优先、集合先行加 Fail-Fast、拒绝天书正则、重构即审判不照抄旧逻辑、契约信任、Radash 与 pathe 物尽其用。

三仓状态：DocsKit 有上一轮 `consolidate-evidence-governance` 的 17 项未提交成果；TeamWiki 与 Ghost 仍有 qing 自己的未提交改动。

## Goals

- `src/core/` 方法体零业务中文，中文只存在于显式业务预设。
- 所有策略数值单一真理源，纯计算函数行为逐字不变。
- 重点模块按第一性重新设计，消灭手搓递归、非空断言、命令式累加与捕获组正则。
- 注入中文预设得到平实的中文卡片，下游迁移成本压到一行注入。
- 代码、测试、文档、规约四处同生共死。

## Non-Goals

- 不改纯计算函数的数值结果。
- 不引入新依赖，不动惰性加载契约。
- 不改下游工作树。
- 不删既有导出符号。

## Decisions

### D1 中文移到显式业务预设

**方案**：`src/core/texts.ts` 定义各模块文案接口与中性默认值，`src/presets/zh-cn.ts` 集中原中文，`docskit/presets` 子路径导出。

**备选**：把中文抽成模块内常量对象，方法体引用常量。

**理由**：备选只是把中文从方法体挪到同文件顶部，引擎仍然持有业务语义。显式预设让「这是可选业务适配层」在目录结构上一眼可见，也允许第二个消费方注入自己的语言。

### D2 渲染类函数改注入式模板

**方案**：`parseMarkdownWithAST` 只产结构；卡片装配由 `DistillTexts` 字典驱动，默认渲染器只用输入数据拼骨架（H1、原文标题、代码块、表格），零自造文案。

**备选**：保留原渲染流程，把每段中文替换成 `texts.xxx` 查表。

**理由**：原流程自己造章节标题、兜底阶段与红线模板，这些本身就是业务决策。第一性看，引擎该把原文结构交给调用方，模板是调用方的事。

### D3 诊断类返回值默认结构化

**方案**：`reason`、`detail`、`advisory`、`message` 默认返回语义化 code（如 `exact_title_hit`），中文句子由预设的格式化函数产出。

**备选**：返回值继续带中文，只把字符串挪到预设。

**理由**：诊断结论是数据，展示是视图。返回值带中文会逼每个消费方解析句子，也让 code 无法稳定断言。

### D4 策略数值单一真理源

**方案**：`src/core/policy.ts` 导出冻结常量表，按模块分组；各文件解构引用，options 覆盖。

**备选**：每模块各建 `defaults.ts`。

**理由**：分散文件仍会多头维护。单一表便于审计「项目一共有多少个可调阈值」，也符合公共底座优先。

### D5 正则按源头消灭

**方案**：MDAST 节点遍历用 `unist-util-visit`，路径用 `pathe`，集合用 `radash`，模式路由用 `picomatch`；确需保留的简单判定收敛到具名常量并附 Shape By Example 注释，禁捕获组回引与多层嵌套。

**备选**：保留全部正则，只补注释。

**理由**：qing 对天书正则是生理性反感，补注释不能改变可读性。

### D6 契约信任

**方案**：`link.position!` 改先过滤出带 position 的节点，`?? 0` 隐式兜底改显式解构，非法入参用 `assert` 当场中断。

**备选**：保留兜底，加 `as` 断言消除类型报错。

**理由**：隐式兜底让脏数据合法化，`as` 是掩耳盗铃。

### D7 新增 presets 子路径

**方案**：`package.json exports`、`tsup.config.ts` entry、`src/index.ts` barrel 三处同步登记 `./presets`。

**备选**：预设挂到根 barrel，不新增子路径。

**理由**：`AGENTS.md` 要求消费方一律子路径导入，挂根 barrel 会破坏这条契约。

### D8 就地施工不开 worktree

**方案**：在当前工作树重构，靠 diff 与测试回滚。

**备选**：先提交上一轮成果，再开 worktree 隔离。

**理由**：qing 只授权了重构，没有授权提交。worktree 基于 HEAD 会丢掉上一轮 17 项未提交成果，制造分裂而非隔离。

## 数据流

```text
调用方注入 ZH_CN_*_TEXTS（可选）
        ↓
src/core/texts.ts 的中性默认值 ← 覆盖 → 业务预设
        ↓
src/core/policy.ts 冻结策略表 ← options 覆盖
        ↓
纯函数：输入 Markdown / 数据 → 结构化结果（零中文）
        ↓
渲染类：结构 + 注入模板 → Markdown / 提示词
诊断类：结构化 code → 预设格式化函数 → 中文句子
```

## 兼容性设计

纯计算类函数加改前后同输入快照断言。渲染与诊断类函数加「注入中文预设后含平实中文模板」断言。根 barrel 导出名集合构建前后比对，旧集合必须是新集合的子集。

## 测试策略

现有测试里中文大多是输入数据，只有 `vault-recipes.test.ts` 的 `/建模范式/`、`/核心架构约束对账/` 依赖引擎自造中文，改为结构断言并补预设注入断言。`layer-1.test.ts` 的附件表格数据行断言保持不变，因为数据行来自输入而非文案。新增 `tests/engine-purity.test.ts` 覆盖零中文、策略表生效、预设恢复、纯函数等价。
